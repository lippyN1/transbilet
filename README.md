# WayGo — билеты на транспорт

**Вариант:** собственная тема на основе варианта 17 «Покупка билетов на транспорт».  
**Стек:** HTML5, CSS Grid/Flexbox, JavaScript `fetch`, FastAPI, SQLite, Docker.

## Что реализовано

- **ПР 1:** шесть связанных страниц, семантическая разметка, единый `static/style.css`, собственный текстовый логотип, адаптивная сетка, каталог из 12 маршрутов.
- **ПР 2:** поиск и фильтрация каталога, сортировка по цене/длительности, выбор маршрута, форма обратной связи, получение данных через `fetch`; конвертация цены в EUR через публичный Frankfurter API с запасным вариантом при недоступности сети.
- **ПР 3:** FastAPI, SQLite, регистрация и вход, безопасное хеширование паролей PBKDF2-HMAC, сессии-токены, личные бронирования, схема мест, запрет двойного бронирования места.
- **ПР 4:** Dockerfile, Compose, health-check endpoint, инструкция по развёртыванию и HTTPS.

Маршруты и тарифы демонстрационные, не являются реальными предложениями перевозчиков. Оплата не подключена: приложение создаёт учебное бронирование в локальной базе данных.

## Запуск локально

Требуется Python 3.11+.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app:app --reload
```

Откройте http://127.0.0.1:8000. Документация API: http://127.0.0.1:8000/docs. База `waygo.db` создаётся автоматически при запуске.

## Запуск через Docker

```bash
docker compose up --build -d
docker compose logs -f
```

Приложение будет доступно на http://localhost:8000. Данные SQLite сохраняются в Docker volume `waygo_data`.

## Публикация в интернете и HTTPS (ПР 4)

1. Загрузите проект в Git-репозиторий.
2. Разверните его на VPS с установленным Docker; откройте входящие порты 80 и 443.
3. Запустите `docker compose up --build -d` и проверьте `/health`.
4. Направьте DNS-запись домена на IP сервера.
5. Настройте обратный прокси Caddy или Nginx перед портом 8000. Caddy автоматически получает и обновляет сертификат Let's Encrypt при корректном DNS и доступных портах 80/443.
6. Для Caddy используйте, например, такой `Caddyfile` (замените домен на свой):

```text
tickets.example.com {
    reverse_proxy 127.0.0.1:8000
}
```

Для публичного запуска дополнительно нужны резервные копии БД, ограничение частоты входа, политика конфиденциальности и реальные данные перевозчиков. Не публикуйте тестовые пароли и секреты. Демо-приложение не принимает платежи.

## Кратко для защиты

- HTML задаёт семантическую структуру, CSS Grid/Flexbox — адаптивный макет.
- JavaScript получает маршруты из `/api/trips` через `fetch`, а не держит каталог только в HTML.
- FastAPI проверяет входные данные и возвращает JSON; SQLite хранит пользователей, сессии, маршруты, бронирования и сообщения.
- Пароль не хранится в открытом виде: в БД сохраняются соль и PBKDF2-хеш.
- Ограничение `UNIQUE(trip_id, seat)` не позволяет двум пользователям занять одно место на одном рейсе.
- Docker упаковывает приложение и зависимости; HTTPS настраивается на сервере через обратный прокси.


### Карта и погода

Страница `/explore` использует геокодирование и текущую погоду Open-Meteo, а интерактивная карта построена на Leaflet с картографическими данными OpenStreetMap. Для демонстрационного некоммерческого использования ключ API не требуется; соблюдайте условия и атрибуцию поставщиков.

Каталог по умолчанию сортирует предложения по цене от большей к меньшей.
